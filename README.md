# 区域预算执行监控与 AI 归因分析助手

一套面向多区域预算管控场景的自动化工具：**对当月《预算使用明细表》做端到端独立重算核查**，再接入大模型生成超支归因分析与管理简报初稿，供人工复核后发布。

> 本仓库为**脱敏演示版**：随附数据由 `src/generate_fake_data.py` 生成，表结构与真实业务模板一致，金额、主体均为虚构。真实环境中，人工逐格核对一张汇总表约需 2 小时；本工具约 3 秒完成全部六项检查。

## 它解决什么问题

多区域预算月报的三个真实痛点：

| 痛点 | 方案 |
|---|---|
| 汇总表靠 SUMIFS 公式取数，公式引用错列/漏行肉眼难发现 | **不信任表内公式缓存**：从三张底表（差旅费/费用明细/专业费用）独立聚合重算，与汇总表逐格比对（容忍 50 元尾差） |
| 模板每月可能增删科目行，写死行号的核对脚本会误报 | **按科目名动态定位**：科目行、总计行全部从 A 列文本识别，模板增删行不误报 |
| 超支了只知道超了多少，归因和简报要人工写 | 核查结果输出结构化指标，**LLM 只做解释、不做计算**，按固定归因维度菜单生成简报初稿，人工复核后发布 |

## 快速开始

```bash
pip install -r requirements.txt   # 仅依赖 openpyxl
python src/run_all.py             # 首次运行自动生成演示数据
```

Windows 用户直接**双击 `run.bat`**。

运行输出（演示数据）：

```
[1/2] 预算核查（独立重算，不信任表内公式缓存）...
      结构自检（科目行 / 区域列）: ✓ 与模板一致
      逐格重算（三张底表独立聚合）: ✓ 54 格 0 差异（容忍 50 元）
      父行(专业费用) = 子行加总: ✓ 6 区域全部相等
      总账闭环（授予/已用/剩余勾稽）: 5/5 项通过
      尾差分解: +46000 元（含已知豁免 46000 元，已解释）
      超支扫描（已用 vs 授予）: 3 条（业务问题，需说明）
[2/2] AI 归因简报 ...
      结论: 表正确；3 条超支待业务说明（见 AI 归因简报）
```

接入自己的月表：把主工作簿放到 `data/预算使用明细表/<N>月/预算使用明细表.xlsx`（需含 `汇总` 与 `授予额度` sheet），或 `python src/monthly_budget_check.py --file <路径>`。

## 六项检查

| # | 检查 | 查什么 | 防什么错 |
|---|---|---|---|
| 1 | 结构自检 | 科目行按名定位、核心科目存在、顺序、区域列头 | 模板被改、区域列错位 |
| 2 | 逐格重算 | 汇总"科目×区域"已用值 vs 底表独立聚合 | SUMIFS 引用错列 / 漏行 |
| 3 | 父行=子行 | 专业费用父行 = 展开子行加总（6 区域） | 层级重复计数或遗漏 |
| 4 | 总账闭环 | 授予/已用/剩余勾稽、底表合计 vs 总计 | 总计行公式错 |
| 5 | 超支扫描 | 逐科目逐区域 已用 vs 授予（专业费用按大类池） | 超支漏报 |
| 6 | 尾差分解 | 底表合计 − 汇总已用的差额逐项列明 | 长科目名未匹配、#N/A 行 |

## AI 归因简报

`src/ai_report.py` 读取核查结果的结构化指标（执行率、超支清单、尾差），生成 `reports/AI归因简报_<月>.md`。

**防幻觉设计**（这是本工具 AI 部分的核心取舍）：

- 指标全部由 Python 计算，模型只做解释，不做任何计算；
- 归因限定固定维度菜单：进度集中（时点错配）/业务量增加/单价上升/一次性项目/统计口径差异；
- 简报强制标注"AI 生成初稿，待人工复核后发布"。

两种模式：

1. **规则模板模式**（默认，零配置）：按科目类型套用归因模板，离线可完整跑通；
2. **LLM 模式**：`cp config.example.json config.json` 并填入 `api_key`，任何 OpenAI 兼容接口均可（DeepSeek/通义/智谱等，改 `base_url` 与 `model` 即可）。

## 设计取舍

- **为什么不用 pandas？** 单文件、单依赖，财务同事机器上 `pip install openpyxl` 即可用；openpyxl 直读已足够。
- **为什么核对脚本独立重算而不是检查公式？** 公式缓存的值可能是保存时的旧值；底表才是唯一事实源。
- **为什么科目行按名定位而不是写死行号？** 模板每月有增删（如零发生科目行删除），写死行号的脚本第二个月就误报。
- **为什么 AI 只出初稿？** 归因结论要发给管理层，错一个判断的责任远大于省下的复核时间——AI 负责把 80% 的格式化工作做掉，人负责最后 20% 的判断。
